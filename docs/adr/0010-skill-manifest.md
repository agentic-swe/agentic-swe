# ADR-010 — Skill manifest: semver, content digest, provenance, external eval attestation; no implicit shadowing

- **Status:** Accepted
- **Date:** 2026-11-12
- **Decider:** founder
- **Related:** ADR-001, ADR-006, ADR-009, ADR-011, ADR-016; master prompt §8 M3.1–M3.6 / §15 / §16; RFC AE-010 §5.5; SEC-006; PD-29..PD-34

## Context

M3 needs a portable skill specification and a registry that can discover, validate, install, version, and promote skills without inventing evidence (master prompt §8 exit; §16 governed promotion). On `origin/main` @ `a453b2f`:

- ~183 `skills/*/SKILL.md` files are generated by `scripts/generate-skills.cjs` from `commands/`, `phases/`, and `agents/subagents/`.
- Frontmatter carries string `metadata:` fields (`name`, `description`, `tier`, `eval_status`, `eval_ref`, `version` pinned `1.0.0`, `provenance*`, `kind`, `source`, `model`, `tools`). There is **no** `schemas/skill-manifest.schema.json`, no structured inputs/outputs/dependencies/permissions/runtime/compatibility objects, and no content digest of the skill body.
- `scripts/skill-lint.cjs` checks name regex, directory match, description length, and `eval_status` set / golden-eval refs — not Ajv against a versioned manifest schema.
- `scripts/lib/skills/eval-gate.cjs` fail-closes autonomous use for `unevaluated` / `lint_passed` / `deprecated`, but `eval_status` is **self-declared** in frontmatter (SEC-006).
- `scripts/lib/skills/project-skills.cjs` lists pack skills then **silently overrides** same-named project skills under `.agentic-swe/skills` (no trust entry) — SEC-006 shadowing gap.
- Tool execution already has an accepted contract (ADR-009): argv-only, `minimalChildEnv`, digest-pinned tool registry, PDP before spawn. ADR-009 states argv is **hygiene, not a sandbox**; OS/container isolation was deferred.
- `config/layers.json` places `skills` in layer `service` and `tools` in `runtime`; `service → runtime` is **forbidden**. Skill packages must not `require` tool-runner modules.
- Pack install digests live under `scripts/lib/install-state/*` (pattern to reuse for skill lockfiles, wrong object today).
- Founder answers for M3 (PD-30..33): registry = **local files + git tags** (no hosted service); sandbox = **process-level** ADR-009 envelope; keep `@agentic-swe` / in-tree paths (`@autoeng` deferred); PD-9 paid LLMs stay off; AE-028b external publication deferred until PD-6; sandbox/policy baseline changes need §15 approval.

A one-line RFC title cannot bind M3 code. This ADR states the manifest, digest, provenance, attestation, shadowing, and M3 registry shape.

## Decision

Every skill the pack or a project installs is described by a schema-valid **SkillManifest** (Ajv; versioned schema under `schemas/`). Required fields align with master prompt §8 M3.1: name, version (semver), description, inputs, outputs, dependencies, permissions (explicit; empty `[]` allowed only when execution rights are none), runtime requirements, compatibility, validation rules, provenance, maintainer. Lint (`skill-lint.cjs` / successors) rejects invalid manifests.

**Content digest.** `digest` is sha256 of the canonical skill body (SKILL.md body after frontmatter, or the locked package payload). Resolve/verify fails closed if body ≠ digest. A **lockfile** pins name → version → digest; tampering fails closed. Install refuses lifecycle scripts / postinstall equivalents and refuses network unless an injected allow-listed transport is present (default deny).

**Provenance.** Typed provenance block: `origin` (`first-party` | `third-party` | `generated` | `unknown`), license, authors, optional upstream repo/commit. Legacy string `provenance*` metadata may load as reduced trust (`origin: unknown`) until migrated (RFC P3); autonomous use stays blocked until trust and eval gates pass.

**Eval attestation.** Autonomous promotion and autonomous selection require an **external** eval result digest (suite id + `result_digest` + timestamp), not self-declared `eval_status` alone. Existing `lint_passed` / `unevaluated` remain manual-only under the eval gate. Golden-eval / contract harnesses produce the external digest that attestation references.

**No implicit shadowing (SEC-006).** Project skills under `.agentic-swe/skills` **must not** replace pack skills of the same name for autonomous use unless an explicit trust entry records the shadow. With trust, resolve records `shadow: explicit`. Without trust, reject for autonomous paths; manual inspection may still read the project file.

**Registry (M3, PD-30).** The skill registry for M3 is **local files in the repo plus git tags** for immutable version pointers. There is **no** hosted registry service, GHCR feed, or npm skill publish path in this ADR. `SkillRegistry.resolve(name, range, trust)` / `verify` / `lock` operate on the local index and lockfile. Republishing the same version with a different digest fails `VERSION_IMMUTABLE`. Deprecate warns; revoke blocks **new** installs. Revocation list is local (and tag/ref conventions documented in AE-025b). External publication of third-party skills (AE-028b) is **out of scope** until PD-6 (PD-32). Digest in the lockfile is authoritative over tag names if a tag moves.

**Execution boundary (PD-31).** Skill/plugin side effects execute only through the ADR-009 tool runner: argv-only, `minimalChildEnv`, PDP on every run, network deny-by-default, grants never from caller input. This ADR does **not** claim OS-user or container/VM isolation. Honest labeling per ADR-001: process envelope is enforced for pack-dispatched tools; host-native tools in in-host mode remain cooperative. Do not label process hygiene as a sandbox boundary under ADR-001 hosted claims.

**Scope naming (PD-33).** Published/packaged skill identity stays **`@agentic-swe` / in-tree paths**. No `@autoeng/*` in manifests until PD-11/PD-22 are resolved.

**Spend (PD-33).** Routing, eval, and smoke stay fixture/local/$0; paid LLM providers remain denied unless the founder reopens PD-9.

**Governed promotion (§16).** Promote only after evidence → isolated tests → compare → independent review → human approval where required → promote → monitor/rollback. Never silently publish private org knowledge to a public skill ecosystem. First-party maintainer promotion inside the pack is allowed under FD-B; external contributor publication waits on PD-6 / AE-028b.

**Layering (ADR-016).** Manifest, lint, registry index, and lockfile code live under `scripts/lib/skills` (`service`) + `schemas/`. Spawn/sandbox enforcement stays in `scripts/lib/tools` + `shared/child-env` (`runtime` / `storage`). Runtime/clients wire them. **No new `service → runtime` edges; zero dependency cycles.**

**Security-policy surface (PD-33 / §15).** Changes that expand default skill permissions, restricted-ops, or sandbox/policy baselines are **security policy changes** and need explicit founder §15 approval before merge (same pattern as AE-022 / PD-23).

## Consequences

- AE-024a/b implement schema, lint, digest, lockfile, and shadow trust before registry invoke claims.
- AE-025a/b implement local resolve/install/immutability/revoke on files + git tags (PD-30).
- AE-026*/AE-029* stay PD-9 offline for routing/eval.
- AE-027a/b extend ADR-009 process profiles; §15 approval when baseline policy changes (PD-31, PD-33).
- AE-028a ships templates + CI validation; AE-028b stays deferred (PD-32).
- Legacy skills migrate incrementally; AE-029a’s ten validated skills lead.
- Accepted 2026-11-12 as amended in `m3-adr-review.md` A1–A4 (PD-34).

## Alternatives

- Hosted registry / GHCR / npm skill packages in M3: rejected for M3 by PD-30; revisit after M3 exit.
- Container/gVisor or OS-user isolation for plugins: rejected for M3 by PD-31; revisit if public untrusted installs ship.
- Self-attested `eval_status` as sufficient for autonomous use: rejected (SEC-006).
- Silent project override of pack skills: rejected (SEC-006).
- Skipping an ADR file and coding from the RFC one-liner: rejected (§13 / M2 gate pattern).
